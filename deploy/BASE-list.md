### The 41st call — a v4 pool the sweep cannot reach

Appended after the batch was first generated, by
`script/append-v4pool.mjs` (which decodes the multicall, pushes one call, and
proves every earlier call is byte-identical before rewriting the file):

```
setExtra(
  0xaba60ba16815f38375928895eb5685ed3aa63aff5c00cca390da03f054b8e769,  // Base USDC listing
  0x95a932c205571d4d1ca72715c642a2eca21dde79ffc28ff11509681f9383385f,  // keccak256("zfi.v4pool")
  "v1:0:3000:10:0"
)
```

Base has a live ETH/USDC v4 pool at fee 3000 with tickSpacing **10**. The
aggregate sweep asks for fee 3000 only at spacing 60, on every chain, so this
pool is invisible to it and always was — the `(fee, spacing, hooks)` space is
unbounded and cannot be swept. Publishing the key here is what lets the page
price it, through `V4QuoteLensL2`. Found by `node script/check-v4-coverage.mjs`;
0.01 ETH quotes 2.055 USDC through the deployed lens.

Note the key is passed as a HASH. The renderer prints an all-printable-ASCII key
as a word and anything else as hex, and the page matches the hex — written as
`bytes32("zfi.v4pool")` it would store fine, render fine, and never be read.

Verify before sending — two tests, and both matter:

```
FOREIGN_LISTING=deploy/BASE-list.calldata.txt forge test --match-path test/ForeignListingTx.t.sol
forge test --match-path test/V4PoolExtraL2.t.sol
```

The first replays this exact calldata against a mainnet fork as the owner and
reads every listing back. The second replays it and then reads the pool key out
of `json(id)` the way the page fetches it, and quotes that pool through the lens
deployed on Base — a key that round-trips into a dead pool is still a dead route.
